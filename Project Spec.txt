In professional development, nobody writes a package.json file by hand from scratch. It is always generated automatically by a tool.
The Modern React Setup Workflow
1) Open an empty folder in VS Code (e.g., C:\Dev\React\).
2) Open your Bash terminal inside VS Code.
3) Run the initialization command:
//Bash
npm create vite@latest

What Vite Does For You Automatically
The moment you finish those prompts, Vite instantly creates a new folder with your project name and scaffolds the entire ecosystem perfectly. It automatically creates:

A pre-configured package.json with React and Vite already listed as dependencies.

A perfect vite.config.js already pointing to the React plugin.

The index.html placed exactly where Vite expects to find it.

A /src folder containing a working main.jsx, App.jsx, and CSS files to get you started.

The Final Steps to Boot It Up
Because Vite sets up the recipe but doesn't download the heavy files immediately, you just have to run three quick commands to dive into coding:

Bash
cd my-new-pos      # Move your terminal inside the new project folder
npm install        # Download all the dependencies listed in the new package.json
npm run dev        # Spin up the local development server

Normally, you create a project using one of two methods:

The Blank Slate Method (npm init -y): This is what we just did. You create an empty folder, run that command, and npm instantly drops a generic blueprint file into your directory. From there, every time you run npm install <package-name>, npm automatically updates that file for you, tracking your dependencies.

// npm create vite@latest
The Automated Scaffolder (e.g., npm create vite@latest): This is the industry standard. Instead of you creating folders and files manually, you run one command, and Vite generates the entire ecosystem for you—the folders, the boilerplate components, and a perfectly pre-configured package.json containing everything a React app needs to boot up.

App.jsx                 ? owns cartItems state + handlers
+-- Menu.jsx            ? receives MENU list + onAddItem callback
+-- OrderSummary.jsx    ? receives cartItems + onRemoveItem callback


State shape
cartItems lives in App.jsx as an array of objects. Each object represents one unique fruit in the cart:
js[
  { id: 1, name: "Apple",  price: 1.50, qty: 2 },
  { id: 3, name: "Mango",  price: 2.00, qty: 1 },
]
When the user clicks Add on a fruit that's already in the cart, qty increments. If it's not in the cart yet, a new object is pushed with qty: 1.

Static data (not state)
The menu itself never changes, so it's a plain array defined outside any component � no useState needed for it:
jsconst MENU = [
  { id: 1, name: "Apple",      price: 1.50 },

What each piece does
FileResponsibilitymenuData.jsSingle source of truth for fruit names, IDs, pricesApp.jsxOwns cartItems state, defines handleAddItem and handleRemoveItem, passes them down as propsMenu.jsxRenders a button for each fruit; calls onAddItem when clickedOrderSummary.jsxRenders the cart rows, calculates and shows the running total

Props flow (the whole learning point)
App.jsx
  cartItems state  --------------------------? OrderSummary.jsx
  handleAddItem()  --? Menu.jsx (as onAddItem prop)
  handleRemoveItem() -------------------------? OrderSummary.jsx (as onRemoveItem prop)
Menu.jsx never sees the cart. OrderSummary.jsx never sees the menu. App.jsx is the bridge. That separation is exactly what makes this a clean teaching example.

Features (v1 only)

Add fruit ? appears in order summary with qty 1; clicking again increments qty
Remove button per row ? decrements qty; if qty hits 0 the row is removed
Running total auto-calculates from cartItems
No checkout, no backend, no localStorage yet � those are v2 ideas
